# Bulletin CTI — Lundi 23 novembre 2026 (mi-journée)

> [!abstract] Niveau de menace : **Élevé**
> Deux exploitations actives sans CVE corrigeable classique : une RCE pré-auth dans une bibliothèque ASP.NET abandonnée (aucun correctif) et une compromission de routeurs GL.iNet via leur cloud de gestion.
> Période : lun. 23/11 07:00 → 13:40 (heure de Paris)

## L'essentiel (BLUF)
- 🔴 P1 **Idunno.AntiCsrf (CVE-2026-131914) :** RCE pré-auth par désérialisation dans une bibliothèque anti-CSRF ASP.NET abandonnée depuis 2008, exploitée selon Mandiant ; aucun correctif : retirer la bibliothèque et chercher AntiCsrfModule dans Web.config.
- 🔴 P1 **GL.iNet GoodCloud :** le service cloud a servi à exécuter du code root et poser un malware sur routeurs et KVM ; mettre à jour le firmware, réinstaller proprement et bloquer les IOC.
- 🟠 P2 **Cisco Expressway (CVE-2026-76466), élément nouveau :** déjà traité ce matin ; nouveau : exploitation rapportée contre une organisation russe peu après la publication d'un PoC public. Échéance KEV atteinte aujourd'hui.
- ⚪ P3 **CERT-In : fraudes assistées par IA :** détournement de workflows d'approbation de paiement dans des banques et fintechs indiennes ; surveiller les changements de RIB fournisseurs et de circuits de validation.

> [!danger] 🔴 P1 · RCE pré-authentification dans Idunno.AntiCsrf (ASP.NET), exploitée, sans correctif
> `CVE-2026-131914` · CVSS **9,3** (4.0 (3.1 N/A)) · EPSS 0,006 (p50,4) · KEV non · Exploitation : Oui (Mandiant, MNDT-2026-0048) · PoC : Inconnu
> **Produit :** Idunno.AntiCsrf ≤ 0.9.1 Beta (ASP.NET / IIS)
> **Type :** Désérialisation de données non fiables → RCE (CWE-502)
> **Correctif :** Aucun (projet abandonné depuis 2008)
>
> **Quoi ?** Désérialisation non sûre dans AntiCsrfModule, module anti-CSRF ASP.NET historique toujours présent dans des applications legacy.
>
> **Comment ?** Le jeton CSRF du formulaire est désérialisé par ObjectStateFormatter sans clé ni vérification MAC : un seul POST avec un cookie CSRF non vide et une gadget chain en Base64 exécute du code dans w3wp.exe.
>
> **Pourquoi c'est important ?** Exploitation active observée par Google/Mandiant, sans authentification, et aucun correctif ne viendra : seule la suppression de la bibliothèque protège.
>
> **Détection** Chercher Idunno.AntiCsrf ou AntiCsrfModule dans Web.config et bin/ ; POST anormaux vers des .aspx renvoyant 302 ou 500 ; processus enfants (cmd, powershell) de w3wp.exe.
>
> **Remédiation** Remplacer par System.Web.Helpers.AntiForgery, ViewStateUserKey avec ViewState signé (MAC) ou IAntiforgery d'ASP.NET Core. Si compromis : rotation machineKey, clés et identifiants BDD, audit des webroots.
>
> Sources : [The Hacker News](https://thehackernews.com/2026/11/hackers-exploit-critical-aspnet-anti.html) · [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-131914)

> [!danger] 🔴 P1 · GL.iNet GoodCloud : exécution root à distance sur routeurs et KVM, exploitée (pas de CVE)
> `` · CVSS **N/A** (N/A) · EPSS N/A (pN/A) · KEV non · Exploitation : Oui (GL.iNet, RemoteToHome) · PoC : Inconnu
> **Produit :** Routeurs GL.iNet (GL-MT3000, MT6000, MG1300, AXT1800, AX1800…) et KVM GL-RM1/RM4PE/RMQ1 avec GoodCloud activé
> **Type :** Commande cloud exécutée en root sans contrôle
> **Correctif :** Correctif cloud (vendredi) + firmware 4.11.1 / 4.8.4 / RM 1.10.3 / RMQ1 1.8.7
>
> **Quoi ?** Faille du service de gestion à distance GoodCloud exploitée pour installer un malware sur des routeurs et KVM clients. Nombre d'appareils, acteur et date de début : N/A.
>
> **Comment ?** Le client GoodCloud contient un handler qui exécute en root deux valeurs reçues d'un message cloud, sans vérification (code présent depuis décembre 2024). Reverse shell root observé vers une IP externe.
>
> **Pourquoi c'est important ?** Le correctif cloud n'efface pas le malware déjà installé. Un KVM compromis donne un accès clavier/écran aux serveurs qu'il pilote.
>
> **Détection** Processus « crond -i /tmp/.log » ; en SSH : ps | grep tmp (routeur) ou ps -aux | grep tmp (KVM) ; trafic vers les IOC listés.
>
> **Remédiation** Mettre à jour le firmware, puis réinstaller proprement sans garder la configuration (recommandation des chercheurs, plus prudente que l'éditeur) ; considérer les secrets stockés comme exposés ; désactiver GoodCloud si inutile.
>
> Sources : [The Hacker News](https://thehackernews.com/2026/11/hackers-exploited-glinet-cloud-flaw-to.html)

## À creuser

> [!tip] Lab
> **Concept :** Une protection CSRF qui désérialise son jeton sans MAC (code d'authentification de message) transforme un contrôle de sécurité en point d'entrée RCE : c'est le cas de CVE-2026-131914, même famille que les attaques ViewState sans machineKey.
>
> **Piste de lab :** Sur une VM Windows isolée (IIS + .NET Framework), monter une page .aspx avec ViewState non signé ; générer un payload ObjectStateFormatter avec ysoserial.net et l'envoyer via Burp Suite. Côté défense : journaliser les processus enfants de w3wp.exe avec Sysmon (Event ID 1) et écrire une règle Sigma, puis activer la validation MAC et vérifier l'échec.
