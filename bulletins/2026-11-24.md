# Bulletin CTI — Mardi 24 novembre 2026

> [!abstract] Niveau de menace : **Élevé**
> Deux ajouts KEV (MONAI Label, N-able MailAssure) à échéance du 26/11, une faille Azure API Management exploitée contre l'énergie norvégienne et le CHU de Guadeloupe paralysé par une cyberattaque.
> Période : lun. 23/11 06:35 → mar. 24/11 06:35 (heure de Paris)

## L'essentiel (BLUF)
- 🔴 P1 **MONAI Label et N-able MailAssure au KEV :** ajoutés le 23/11, échéance CISA au 26/11 ; nouveau : exploitation confirmée. Passer MONAI Label en 0.8.6 et vérifier le build MailAssure/SpamExperts (≥ 20261121.1943).
- 🔴 P1 **Azure API Management Classic :** faille exploitée pour voler les identifiants d'API stockés, liée par la Norvège aux attaques contre Equinor et Skagerak Energi ; faire tourner les secrets stockés dans APIM.
- 🟠 P2 **CHU de Guadeloupe :** plan blanc depuis le 22/11 après une cyberattaque ; vecteur et acteur non communiqués, s'attendre à du phishing opportuniste visant patients et personnel.
- 🟠 P2 **binary-parser (npm) :** injection de code JavaScript (CVSS 4.0 9,2) si l'attaquant contrôle les définitions de parseur ; mettre à jour en 2.3.1.
- 🟠 P2 **Webworm :** l'acteur aligné sur la Chine utiliserait un SoftEther VPN Bridge modifié, déguisé en outil de supervision, pour un accès persistant ; chasser les binaires SoftEther inattendus.

> [!danger] 🔴 P1 · MONAI Label : path traversal menant à une RCE, ajoutée au KEV
> `CVE-2026-133968` · CVSS **9,8** (3.1) · EPSS 0,037 (p89,9) · KEV **oui** · Exploitation : Oui, depuis septembre 2026 · PoC : Inconnu
> **Produit :** MONAI Label < 0.8.6
> **Type :** Path traversal (CWE-24)
> **Correctif :** 0.8.6
>
> **Quoi ?** Faille de MONAI Label, serveur d'annotation d'imagerie médicale par IA. Nouveau : ajoutée au KEV le 23/11, échéance fédérale au 26/11.
>
> **Comment ?** Le paramètre image de l'endpoint PUT /datastore/image permet, sans authentification, d'écrire un fichier hors du datastore, d'où une exécution de code.
>
> **Pourquoi c'est important ?** Exploitée depuis septembre 2026 contre des universités (opération Cairn, agents IA autonomes). Les serveurs de recherche exposés sur Internet sont visés.
>
> **Détection** Requêtes PUT /datastore/image contenant ../ dans le paramètre image ; fichiers Python inattendus (sitecustomize.py) ; processus enfants du service MONAI Label.
>
> **Remédiation** Mettre à jour en 0.8.6, retirer l'instance d'Internet ou la placer derrière une authentification. Si exposée depuis septembre : traiter comme compromise.
>
> Sources : [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2026-133968) · [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-133968)

> [!danger] 🔴 P1 · N-able MailAssure / SpamExperts : SSRF ajoutée au KEV
> `CVE-2026-134624` · CVSS **9,3** (4.0) · EPSS 0,004 (p29,7) · KEV **oui** · Exploitation : Oui (CISA KEV, 23/11) · PoC : Inconnu
> **Produit :** MailAssure (SpamExperts) < 20261121.1943
> **Type :** SSRF (CWE-918)
> **Correctif :** Build 20261121.1943
>
> **Quoi ?** SSRF (le serveur est forcé à émettre des requêtes vers des cibles choisies) dans la vérification de connexion LDAP. Nouveau depuis hier : exploitation confirmée par l'ajout au KEV le 23/11.
>
> **Comment ?** Un utilisateur API authentifié fait connecter le serveur à des hôtes et ports internes arbitraires, cartographie ceux qui répondent et leur envoie des données forgées.
>
> **Pourquoi c'est important ?** Découverte pendant l'enquête sur l'intrusion du Hosted Cloud de N-able. Service de filtrage mail mutualisé par des MSP : un rebond vers l'interne touche de nombreux clients.
>
> **Détection** Journaux API de configuration de relais/LDAP pointant vers des IP privées ou des ports inhabituels ; connexions sortantes du serveur vers le réseau interne.
>
> **Remédiation** Vérifier le build (≥ 20261121.1943) sur Local Cloud, recréer les jetons API/OAuth révoqués et filtrer les flux sortants du serveur vers l'interne.
>
> Sources : [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2026-134624) · [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-134624) · [SecurityWeek](https://www.securityweek.com/n-able-patches-critical-flaw-disclosed-after-mail-assure-cyberattack/)

## Menaces & campagnes

### Norvège : la faille Azure APIM exploitée contre Equinor et Skagerak Energi
- **Quoi ?** Les autorités norvégiennes relient l'exploitation d'Azure API Management Classic à des attaques visant des identifiants sensibles chez Equinor et Skagerak Energi.
- **Comment ?** Vol d'identifiants d'API stockés dans le service cloud, puis usage présumé pour atteindre des systèmes internes (détails non publiés).
- **Pourquoi c'est important ?** Énergie, secteur critique ; montre que les secrets confiés à un service SaaS restent une cible même quand le fournisseur a corrigé.
- **Attribution :** N/A (aucune attribution publiée) · confiance faible

### Webworm : un SoftEther VPN Bridge modifié pour l'accès distant
- **Quoi ?** Webworm, acteur aligné sur la Chine, utiliserait une version modifiée de SoftEther VPN Bridge (VPN open source), déguisée en logiciel de supervision réseau.
- **Comment ?** Les empreintes reconnaissables de SoftEther sont retirées du binaire, qui maintient un tunnel vers l'infrastructure de l'attaquant : accès distant sans malware classique.
- **Pourquoi c'est important ?** Un outil légitime modifié échappe aux signatures ; seules la télémétrie réseau et l'inventaire logiciel le révèlent. Rapid7 évoque des cibles gouvernementales.
- **Attribution :** Webworm, aligné sur la Chine (soupçon des chercheurs) · confiance moyenne
- **TTPs :** [T1572 Protocol Tunneling](https://attack.mitre.org/techniques/T1572/), [T1036 Masquerading](https://attack.mitre.org/techniques/T1036/), [T1133 External Remote Services](https://attack.mitre.org/techniques/T1133/)
- Sources : [The Hacker News](https://thehackernews.com/2026/11/webworm-suspected-of-modifying.html) · [Rapid7](https://www.rapid7.com/blog/post/tr-spying-on-governments-no-malware-custom-webworms-toolkit-softether-bridge)

## À creuser

> [!tip] Lab
> **Concept :** La SSRF (CVE-2026-134624) détourne une fonction du serveur, ici un test de connexion LDAP, pour joindre des hôtes internes. Les différences de réponse ou de délai révèlent les ports ouverts : le serveur devient un scanner derrière le pare-feu.
>
> **Piste de lab :** Sous Ubuntu avec Docker : une app Flask exposant un « test de connexion » (hôte, port) et un Redis interne non exposé. Scanner le réseau Docker via l'app, puis envoyer des commandes Redis brutes. Côté défense : journaliser les destinations, filtrer la sortie par liste blanche et vérifier le blocage.
