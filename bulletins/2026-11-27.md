# Bulletin CTI — Vendredi 27 novembre 2026

> [!abstract] Niveau de menace : **Élevé**
> Nouvelle faille Drupal core exploitée deux jours après Fail2Install, exploitation de Fragnesia confirmée par Palo Alto, brèche chez 1Password et GeoServer attaqué ; collecte du jour absente, couverture partielle.
> Période : jeu. 26/11 06:35 → ven. 27/11 06:35 (heure de Paris)

## L'essentiel (BLUF)
- 🔴 P1 **Drupal core (CVE-2026-136716) :** nouvelle faille « highly critical » exploitée : le correctif Fail2Install laissait des états d'installation vulnérables ; mettre à jour au-delà de 10.6.23 / 11.3.23 / 11.4.14.
- 🔴 P1 **Palo Alto PAN-OS (Fragnesia) :** l'éditeur confirme l'exploitation en chaîne avec PHP2Shell contre les interfaces de gestion exposées ; appliquer le correctif et retirer l'interface d'Internet.
- 🟠 P2 **1Password :** compte GitHub d'un employé piraté, code malveillant déployé en backend, données clients et code source volés, coffres non touchés ; anticiper du phishing ciblé.
- 🟠 P2 **GeoServer (CVE-2026-120705, CVE-2026-129243) :** exploitation observée par watchTowr, chaînables vers une RCE sans authentification ; patcher les instances exposées.
- 🟠 P2 **Mitel MiCollab :** selon Accenture, les failles AWV ajoutées au KEV le 25/11 étaient exploitées en 0-day avant l'avis, probablement avec l'aide d'IA, dans une campagne d'extorsion.

## Menaces & campagnes

### 1Password : données clients et code source volés via un compte GitHub d'employé
- **Quoi ?** Brèche révélée le 25/11 : des données clients et du code source interne ont été volés. Les coffres de mots de passe n'ont pas été consultés selon l'éditeur.
- **Comment ?** Le compte GitHub professionnel d'un employé, compromis, a servi à pousser du code malveillant vers des services backend qui collectaient des données clients. Enquête ouverte le 19/11.
- **Pourquoi c'est important ?** Les clients d'un gestionnaire de mots de passe sont une cible de phishing de choix. Le cas montre aussi qu'un compte de développeur suffit à atteindre la production.
- **TTPs :** [T1078 Valid Accounts](https://attack.mitre.org/techniques/T1078/), [T1213.003 Code Repositories](https://attack.mitre.org/techniques/T1213/003/), [T1565 Data Manipulation](https://attack.mitre.org/techniques/T1565/)
- Sources : [BleepingComputer](https://www.bleepingcomputer.com/news/security/1password-customer-data-stolen-after-employee-github-account-breach/) · [The Hacker News](https://thehackernews.com/2026/11/1password-hacked-customer-data-and.html) · [Next](https://next.ink/brief-article/un-compte-github-compromis-chez-1password-expose-des-donnees-clients/)

### Mitel MiCollab : exploitées en 0-day avant l'avis, probablement avec l'aide d'IA
- **Quoi ?** Nouveau : Accenture indique que les failles AWV de MiCollab, ajoutées au KEV le 25/11, étaient exploitées avant la publication de l'avis Mitel, dans une campagne d'extorsion présumée.
- **Comment ?** Failles du composant AWV sans authentification (injection de commande CVE-2026-133323, CVSS 10, injection XML, upload de fichiers). Usage d'IA présumé par Accenture.
- **Pourquoi c'est important ?** MiCollab est exposé sur Internet pour la collaboration ; l'exploitation précédant l'avis signifie que des instances patchées tardivement peuvent déjà être compromises.
- **Attribution :** N/A (campagne d'extorsion présumée) · confiance faible
- **TTPs :** [T1190 Exploit Public-Facing Application](https://attack.mitre.org/techniques/T1190/), [T1657 Financial Theft](https://attack.mitre.org/techniques/T1657/)
- Sources : [SecurityWeek](https://www.securityweek.com/mitel-micollab-zero-days-exploited-in-suspected-ai-assisted-attacks/) · [The Hacker News](https://thehackernews.com/2026/11/hackers-exploit-10-vulnerabilities.html)

### SYS010 : l'infostealer inscrit les navigateurs en gestion d'entreprise pour lire Gmail et Outlook
- **Quoi ?** Nouvelle version de l'infostealer SYS01, diffusée par des publicités Meta.
- **Comment ?** Le malware place le navigateur sous gestion de type entreprise (politiques) pour forcer l'installation d'une extension qui vole notamment les e-mails Gmail et Outlook.
- **Pourquoi c'est important ?** Une extension imposée par politique ne peut pas être désinstallée par l'utilisateur et survit au nettoyage classique.
- **TTPs :** [T1583.008 Malvertising](https://attack.mitre.org/techniques/T1583/008/), [T1176 Browser Extensions](https://attack.mitre.org/techniques/T1176/), [T1114 Email Collection](https://attack.mitre.org/techniques/T1114/)
- Sources : [BleepingComputer](https://www.bleepingcomputer.com/news/security/sys010-malware-abuses-browser-management-to-spy-on-gmail-outlook/)

## À creuser

> [!tip] Lab
> **Concept :** Les politiques de navigateur (cas de SYS010) : sous Linux, Chrome lit des fichiers JSON dans /etc/opt/chrome/policies/managed ; la clé ExtensionInstallForcelist installe une extension que l'utilisateur ne peut pas retirer.
>
> **Piste de lab :** Sur une VM Ubuntu isolée, créer une politique forçant une extension de test, puis l'observer dans chrome://policy. Côté défense : règle auditd sur /etc/opt/chrome/policies et /etc/chromium/policies, et script listant les extensions forcées du parc.
