# Bulletin CTI — Samedi 28 novembre 2026

> [!abstract] Niveau de menace : **Élevé**
> Trois ajouts au CISA KEV le 27/11 (détail non collecté), RCE root sans authentification dans le serveur NFS du noyau Linux (CVSS 9,8), intrusion chez SAP sur GitHub et logiciels officiels Q-Dir/DesktopOK piégés.
> Période : ven. 27/11 06:35 → sam. 28/11 06:35 (heure de Paris)

## L'essentiel (BLUF)
- 🔴 P1 **CISA KEV (27/11) :** trois vulnérabilités exploitées ajoutées au catalogue ; liste exacte non collectée (une source secondaire cite GeoServer et Drupal, non confirmé). Vérifier le catalogue et patcher en priorité.
- 🟠 P2 **NFS2ROOT (CVE-2026-99362) :** faille de 12 ans du serveur NFS du noyau Linux : tout client atteignant le port 2049 écrit dans la mémoire noyau sans authentification. Corrigée le 19/11 ; mettre à jour le noyau et filtrer le port 2049.
- 🟠 P2 **SAP :** incident confirmé après activité suspecte sur GitHub ; des jetons d'employés volés auraient servi à copier et modifier du code source. Surveiller les avis SAP et l'intégrité des composants récupérés depuis ses dépôts.
- 🟠 P2 **Q-Dir et DesktopOK :** installateurs et mises à jour officiels de SoftwareOK piégés avec un malware d'accès à distance ; vérifier les postes qui ont installé ou mis à jour ces outils récemment.
- ⚪ P3 **AFP :** cyberattaque le 26/11 ayant mis hors ligne une plateforme de distribution de dépêches ; nature de l'attaque N/A. Rester vigilant face aux faux contenus ou phishing se réclamant de l'agence.

> [!warning] 🟠 P2 · NFS2ROOT : écriture mémoire noyau sans authentification dans le serveur NFS Linux
> `CVE-2026-99362` · CVSS **9,8** (3.1) · EPSS 0,008 (p51,4) · KEV non · Exploitation : Non signalée · PoC : Inconnu
> **Produit :** Noyau Linux, serveur NFS (nfsd), NFSv4.1+ ; versions N/A (faille présente depuis 12 ans)
> **Type :** Corruption mémoire noyau → élévation à root à distance
> **Correctif :** Correctif noyau du 19/11 (« nfsd: preflight SEQUENCE replies ») ; versions N/A
>
> Repérée par un chercheur de l'ANSSI. Un client qui négocie une taille de réponse en cache minimale (ca_maxresponsesize_cached) fait déborder le tampon de réponse SEQUENCE. NAS et nœuds Kubernetes servant du NFS sont concernés : appliquer les noyaux des distributions et restreindre le port 2049.
>

## Menaces & campagnes

### SAP confirme un incident de sécurité lié à GitHub
- **Quoi ?** SAP a détecté une activité suspecte dans son environnement et dit avoir agi en urgence pour protéger ses clients. Périmètre exact et données touchées N/A.
- **Comment ?** Selon SecurityWeek, des attaquants auraient utilisé des jetons d'employés volés pour copier et modifier du code source sur GitHub (non confirmé par SAP).
- **Pourquoi c'est important ?** Du code modifié chez un éditeur aussi central peut se propager chez les clients (chaîne d'approvisionnement). Même schéma que l'incident 1Password de cette semaine.
- **TTPs :** [T1078 Valid Accounts](https://attack.mitre.org/techniques/T1078/), [T1213.003 Code Repositories](https://attack.mitre.org/techniques/T1213/003/), [T1195.002 Compromise Software Supply Chain](https://attack.mitre.org/techniques/T1195/002/)
- Sources : [BleepingComputer](https://www.bleepingcomputer.com/news/security/sap-confirms-security-incident-after-suspicious-github-activity/) · [SecurityWeek](https://www.securityweek.com/sap-confirms-cyberattack-source-code-reportedly-compromised/)

### Q-Dir et DesktopOK : téléchargements officiels piégés
- **Quoi ?** Les installateurs de Q-Dir et DesktopOK, utilitaires Windows distribués par le site officiel SoftwareOK, ont été modifiés pour livrer un malware d'accès à distance.
- **Comment ?** Les fichiers malveillants étaient servis depuis la page de téléchargement officielle et aussi lors de la mise à jour de versions déjà installées. Nom du malware et IOC N/A.
- **Pourquoi c'est important ?** Le canal de mise à jour légitime contourne la vigilance de l'utilisateur : même une installation ancienne et saine a pu être compromise.
- **TTPs :** [T1195.002 Compromise Software Supply Chain](https://attack.mitre.org/techniques/T1195/002/), [T1219 Remote Access Software](https://attack.mitre.org/techniques/T1219/)
- Sources : [The Hacker News](https://thehackernews.com/2026/11/hackers-trojanize-official-q-dir-and.html)

### PolinRider : plus de 7 600 dépôts GitHub empoisonnés
- **Quoi ?** La campagne PolinRider a compromis plus de 7 600 dépôts GitHub, dont 86 % appartiennent à de vrais développeurs, avec une activité qui remonterait à février 2025.
- **Comment ?** Dans certains dépôts, un chargeur Python est implanté pour télécharger des charges de second niveau.
- **Pourquoi c'est important ?** Cloner ou exécuter un projet compromis suffit à infecter un poste de développeur et ses secrets (jetons, clés SSH).
- **Attribution :** Lié à la Corée du Nord (selon The Hacker News) · confiance faible
- **TTPs :** [T1195.001 Compromise Software Dependencies and Development Tools](https://attack.mitre.org/techniques/T1195/001/), [T1059.006 Python](https://attack.mitre.org/techniques/T1059/006/)
- Sources : [The Hacker News](https://thehackernews.com/2026/11/north-korea-linked-polinrider-poisons.html)

### Remus : l'infostealer lit Gmail via une fausse extension Google Sheets
- **Quoi ?** L'infostealer Remus vole des messages Gmail grâce à une extension Chrome malveillante déguisée en outil Google Sheets ; ses opérateurs la vendaient comme un « 0-day Gmail ».
- **Comment ?** L'extension s'exécute dans la session déjà ouverte de la victime et lit ses e-mails, sans exploiter de faille de Google.
- **Pourquoi c'est important ?** Contourne la MFA puisque la session est déjà authentifiée ; les e-mails donnent accès aux réinitialisations de mot de passe.
- **Attribution :** Opérateurs du MaaS Remus · confiance moyenne
- **TTPs :** [T1176 Software Extensions](https://attack.mitre.org/techniques/T1176/), [T1114 Email Collection](https://attack.mitre.org/techniques/T1114/)
- Sources : [BleepingComputer](https://www.bleepingcomputer.com/news/security/remus-malware-steals-gmail-messages-via-fake-google-sheets-extension/)

### « GoodGuys » : fausses interviews d'experts rémunérées pour voler des identifiants Google et Okta
- **Quoi ?** Campagne de phishing en cours usurpant Google, Nvidia, Accenture ou SpaceX avec de fausses invitations à des interviews d'experts payées et à des webinaires.
- **Comment ?** Les liens mènent à des pages qui récupèrent les identifiants Google et Okta professionnels.
- **Pourquoi c'est important ?** Vise les comptes SSO d'entreprise : un seul compte Okta ouvre l'accès à toutes les applications fédérées.
- **TTPs :** [T1566.002 Spearphishing Link](https://attack.mitre.org/techniques/T1566/002/), [T1656 Impersonation](https://attack.mitre.org/techniques/T1656/)
- Sources : [BleepingComputer](https://www.bleepingcomputer.com/news/apple/fake-paid-expert-interviews-impersonate-brands-to-steal-google-logins/)

## À creuser

> [!tip] Lab
> **Concept :** NFS2ROOT rappelle que nfsd tourne dans le noyau : une faille dans le serveur NFS donne directement root, sans passer par un service utilisateur à compromettre.
>
> **Piste de lab :** Sur Ubuntu : vérifier l'exposition avec ss -ltnu | grep 2049 et systemctl status nfs-server, comparer uname -r au noyau corrigé de la distribution, puis limiter le port avec ufw allow from <réseau> to any port 2049. Côté détection : journaliser les connexions sur 2049 venant d'hôtes inattendus.
