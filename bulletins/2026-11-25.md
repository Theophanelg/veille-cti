# Bulletin CTI — Mercredi 25 novembre 2026

> [!abstract] Niveau de menace : **Élevé**
> Trois ajouts KEV du 24/11 à échéance du 27/11, dont une RCE Drupal core via l'installateur et la chaîne d'approvisionnement Optimizely (OPTIMJACK, 178 organisations) ; collecte automatique du jour absente, couverture partielle.
> Période : mar. 24/11 06:35 → mer. 25/11 06:35 (heure de Paris)

## L'essentiel (BLUF)
- 🔴 P1 **Drupal core (CVE-2026-132165) :** RCE via l'installateur install.php, ajoutée au KEV le 24/11 ; passer en 10.6.22 / 11.4.13 et bloquer install.php d'ici le 27/11.
- 🔴 P1 **Optimizely Web Experimentation (CVE-2026-132224) :** code JavaScript malveillant injecté dans les scripts projectJS servis par le CDN Optimizely (OPTIMJACK : skimmer et crypto clipper) ; auditer les snippets chargés par vos sites.
- 🔴 P1 **Idunno.AntiCsrf (CVE-2026-131914) :** RCE pré-auth déjà signalée exploitée, désormais au KEV (échéance 27/11) ; sans correctif, retirer la bibliothèque des applications WebForms.
- 🔴 P1 **Volans NGFW r5.1 (CVE-2026-135797) :** injection de commande pré-auth dans le client SSL VPN, CVSS 10, PoC public, éditeur muet ; ne pas exposer l'interface SSL VPN.

> [!danger] 🔴 P1 · Drupal core : RCE non authentifiée via l'installateur, ajoutée au KEV
> `CVE-2026-132165` · CVSS **N/A** (N/A) · EPSS N/A (pN/A) · KEV **oui** · Exploitation : Oui (KEV, ajout 24/11) · PoC : Inconnu
> **Produit :** Drupal core (versions corrigées : 10.6.22, 11.4.13)
> **Type :** Prise de contrôle / RCE via install.php
> **Correctif :** 10.6.22 / 11.4.13
>
> **Quoi ?** Faille critique du site installer de Drupal core permettant une prise de contrôle du site sans authentification.
>
> **Comment ?** Passe par le script install.php accessible à distance ; mécanisme détaillé N/A dans les sources consultées.
>
> **Pourquoi c'est important ?** La CISA confirme l'exploitation active (ajout KEV le 24/11, échéance 27/11) et Drupal avait prévenu que des exploits arriveraient vite. Les CMS sont exposés à Internet par nature.
>
> **Détection** Requêtes HTTP vers /core/install.php ou /install.php sur des sites déjà installés ; nouveaux comptes administrateurs, modules ou fichiers PHP inattendus.
>
> **Remédiation** Mettre à jour vers 10.6.22 ou 11.4.13 ; bloquer l'accès à install.php au niveau du serveur web ; appliquer le triage forensique demandé par la CISA si le site était exposé.
>

> [!danger] 🔴 P1 · Optimizely Web Experimentation : code injecté dans les scripts CDN (OPTIMJACK), ajoutée au KEV
> `CVE-2026-132224` · CVSS **8,7** (3.1) · EPSS 0,004 (p35,8) · KEV **oui** · Exploitation : Oui (KEV, campagne OPTIMJACK) · PoC : Inconnu
> **Produit :** Optimizely Web Experimentation avant le 17/11/2026 (SaaS)
> **Type :** Contrôle externe de données d'état critiques → injection JavaScript côté client
> **Correctif :** Corrigé côté éditeur le 17/11
>
> **Quoi ?** Le flux d'inscription Optimizely laissait un attaquant placer son code dans le champ projectJS d'actifs servis par cdn.optimizely.com.
>
> **Comment ?** Les sites clients chargeaient ce JavaScript de confiance ; il embarquait un skimmer de cartes et un crypto clipper (malware qui remplace les adresses de portefeuille copiées).
>
> **Pourquoi c'est important ?** Attaque de chaîne d'approvisionnement côté client touchant au moins 178 organisations, dont des sites de grands médias. Ajout KEV le 24/11, échéance 27/11.
>
> **Détection** Inventorier les scripts cdn.optimizely.com chargés par vos pages et comparer le projectJS à la version attendue ; alertes CSP (Content Security Policy) vers des domaines d'exfiltration inconnus.
>
> **Remédiation** Vérifier et nettoyer le projectJS de chaque projet, faire tourner les accès Optimizely, imposer une CSP stricte et le SRI (contrôle d'intégrité) quand c'est possible ; notifier les clients si des paiements ont transité.
>
> Sources : [BleepingComputer](https://www.bleepingcomputer.com/news/security/optimizely-supply-chain-attack-delivers-malware-to-cnn-fox-news-bbc-salesforce-sites/) · [StepSecurity](https://www.stepsecurity.io/blog/optimjack-optimizely-hosted-scripts-crypto-clipper-card-skimmer) · [Sophos](https://www.sophos.com/blog/hijacked-optimizely-snippets-served-malicious-code) · [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-132224) · [CISA KEV](https://github.com/cisagov/kev-data)

> [!danger] 🔴 P1 · Idunno.AntiCsrf (ASP.NET WebForms) : RCE pré-auth, désormais au KEV
> `CVE-2026-131914` · CVSS **9,8** (3.1) · EPSS 0,006 (p50,2) · KEV **oui** · Exploitation : Oui (KEV, ajout 24/11) · PoC : Inconnu
> **Produit :** Idunno.AntiCsrf jusqu'à 0.9.1 Beta (ASP.NET)
> **Type :** Désérialisation de données non fiables → RCE (CWE-502)
> **Correctif :** Aucun (bibliothèque abandonnée)
>
> **Quoi ?** Déjà traitée le 23/11 ; élément nouveau : ajout au KEV le 24/11 avec échéance fédérale au 27/11.
>
> **Comment ?** La validation double-submit cookie / champ de formulaire désérialise des objets fournis par l'attaquant : injection d'objet et exécution de code sans authentification.
>
> **Pourquoi c'est important ?** Bibliothèque anti-CSRF ancienne encore présente dans des applications WebForms exposées ; pas de correctif, donc seule la suppression protège.
>
> **Détection** Cookies ou champs anti-CSRF anormalement longs ou encodés en base64 ; processus enfants (cmd.exe, powershell.exe) lancés par w3wp.exe.
>
> **Remédiation** Retirer Idunno.AntiCsrf et le remplacer par la protection anti-CSRF native d'ASP.NET (ViewStateUserKey) ; à défaut, isoler l'application. Échéance KEV : 27/11.
>
> Sources : [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-131914) · [CISA KEV](https://github.com/cisagov/kev-data)

## Menaces & campagnes

### OPTIMJACK : scripts Optimizely détournés pour voler cartes et cryptomonnaies
- **Quoi ?** Campagne de chaîne d'approvisionnement côté client : au moins 178 organisations ont servi à leurs visiteurs du JavaScript malveillant hébergé par Optimizely.
- **Comment ?** Abus du flux d'inscription (CVE-2026-132224) pour écrire dans le projectJS ; charge utile combinant skimmer de cartes et crypto clipper.
- **Pourquoi c'est important ?** Un script tiers de confiance, déjà autorisé par la CSP, contourne la plupart des défenses serveur ; l'ajout KEV du 24/11 confirme la gravité.
- **TTPs :** [T1195.002 Compromise Software Supply Chain](https://attack.mitre.org/techniques/T1195/002/), [T1189 Drive-by Compromise](https://attack.mitre.org/techniques/T1189/), [T1056.003 Web Portal Capture](https://attack.mitre.org/techniques/T1056/003/), [T1565.002 Transmitted Data Manipulation](https://attack.mitre.org/techniques/T1565/002/)
- Sources : [StepSecurity](https://www.stepsecurity.io/blog/optimjack-optimizely-hosted-scripts-crypto-clipper-card-skimmer) · [ReversingLabs](https://www.reversinglabs.com/blog/optimjack-when-trusted-javascript-becomes-a-supply-chain-attack) · [Zscaler](https://www.zscaler.com/blogs/security-research/attackers-exploit-optimizely-flaw-inject-malicious-javascript)

## À creuser

> [!tip] Lab
> **Concept :** Une attaque de chaîne d'approvisionnement côté client (cas OPTIMJACK) modifie un script tiers chargé par le navigateur : le serveur n'est pas touché, mais chaque visiteur exécute le code de l'attaquant.
>
> **Piste de lab :** Sur une VM Ubuntu isolée, servir une page de paiement factice chargeant un script tiers local, puis modifier ce script pour exfiltrer le formulaire vers un second conteneur. Côté défense : ajouter une CSP stricte et un attribut integrity (SRI), observer le blocage dans la console et collecter les rapports CSP avec un petit serveur Python.
